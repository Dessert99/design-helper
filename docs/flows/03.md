# 03. 아무런 디자인이 없는 제로 베이스에서 디자인을 시작하는 상황

[상황 목록으로](../flows.ko.md)

## 시작 조건

만들 대상은 버튼 하나로 정해져 있지만, 기존 버튼 디자인과 사용할 디자인 스케일은 없다. 이 예시의 목표는 첫 비교의 기준이 될 버튼 모습을 고르는 것이다.

## 예시 대화와 스킬 행동

> 사용자: 버튼 디자인이 아무것도 없어. 제로 베이스에서 시작하고 싶어.

1. 기존 디자인의 불만을 묻지는 않는다. 대신 용도·콘텐츠·사용 조건이 불명확하면 필요한 내용을 한 번에 하나씩 확인한다. 탐색 방향과 필요한 후보 수를 상황에 맞춰 정한다. 사용자가 개수를 지정하면 따르고, 원하는 탐색 범위가 애매하면 그리기 전에 한 번 묻는다. 3×3이나 아홉 개로 고정하지 않는다.
2. 두 방향의 관계를 함께 보는 것이 유용하면 매트릭스로 그린다. 예를 들어 가로는 `모서리 — 각짐 → 둥글`, 세로는 `무게 — 가벼움 → 무거움`으로 둔다. 가로로 이동하면 모서리만 달라지고, 세로로 이동하면 무게에 묶인 속성들이 달라진다.
3. `무게 = 테두리 굵기 + 글자 굵기 + 세로 여백`처럼 한 방향에 묶인 속성을 캡션에 공개한다. 사용자는 `무게 말고 밀도로 봐줘`처럼 비교 방향 자체를 바꿔 달라고 할 수 있다.
4. 실제로 제시한 후보에 A부터 문자를 붙이고 채팅으로 출발점을 받는다. 기존 토큰을 변경하는 상황이 아니므로 토큰 변경 비용칩은 표시하지 않는다.

> 사용자: E에서 시작하자.
>
> 에이전트: 출발점: 버튼 = E · 무게 중간 · 모서리 중간 (묶인 속성 전부 미해결)

채팅의 `E에서 시작하자`는 출발점으로 기록한다. E를 고른 이유가 모서리 때문인지, 글자 굵기나 여백 때문인지 아직 분리해 확인하지 않았으므로 각 속성을 확정한 것으로 간주하지 않는다. 다음 비교에서는 E의 속성값들을 기준으로 사용한다.

### 사용자가 다음 비교를 주문하면

> 사용자: 이 출발점에서 모서리만 비교해줘.

E의 나머지 속성을 유지하고 모서리 한 축의 표본을 그린다. 백지 좌표 탐색은 끝났으며, 에이전트가 다음 축을 먼저 제안하지 않는다.

## 끝나는 지점

주 흐름은 출발점을 기록하는 데서 끝난다. 이후 단일 축 비교는 별도 사용자 주문으로 시작한다.

## 다른 상황과의 차이

[02](02.md)에는 불편함을 살펴볼 기존 디자인이 있다. 이 상황에는 그것이 없어 좌표 탐색으로 시작한다. 좌표에서 고른 출발점과 [01](01.md)의 단일 속성 확정은 의미가 다르다.
