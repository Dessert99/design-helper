# 11. 확정한 값을 실제 코드에 반영하고 확인하는 상황

[상황 목록으로](../flows.ko.md)

## 시작 조건

카드 비교에서 사용자가 `난 B가 좋아`라고 선택했다. 선택은 해당 카드에 반영하라는 요청이다. 예시에서는 이 카드의 블러와 모서리가 다른 컴포넌트도 사용하는 공통 토큰에 연결되어 있다고 가정한다.

## 예시 대화와 스킬 행동

> 사용자: 난 B가 좋아.

1. 메모에서 확정값을 확인한다. 단순한 인상, 언급만 한 대안, 백지 탐색의 출발점을 확정값으로 추가하지 않는다.
2. 실제 파일·줄·토큰과 연결된 사용처를 확인해 영향 범위를 보고한다. 비교 중 표시했던 비용칩의 숫자를 그대로 최종 집계로 사용하지 않는다.
3. 기존 토큰 재사용이나 해당 카드의 지역 변경으로 선택값을 적용한다. 공유 토큰 전체 변경은 이미 그 범위가 요청된 경우에만 진행한다. 범위를 판단할 수 없는 필수 결정만 질문한다.

공통 토큰은 유지하고 이 카드에 확정값을 적용한다. 사용자가 실제 화면을 확인할 수 있도록 변경 위치와 확인할 부분을 안내하며, 시트와 서버는 계속 유지한다.

> 사용자: 실제 화면에서 확인했어. 됐어.

시트와 서버를 유지하던 세션을 종료하고, 스킬이 만든 임시 작업 폴더와 프로세스를 정리한다.

## 끝나는 지점

사용자가 실제 결과를 확인하고 종료를 알린 뒤 임시 자원을 정리하는 데서 끝난다. 코드 반영 승인을 받은 시점에 바로 시트를 없애지 않는다.

프로젝트에 비교용 임시 파일이 남았는지 확인하되, 반영한 코드와 기존 사용자 변경은 보존한다.

## 다른 상황과의 차이

[01](01.md)과 [05](05.md)의 선택 직후 이어지는 반영 절차다. 별도 반영 주문을 기다리지 않으며, 사용자가 실제 결과 확인을 마치면 임시 비교 환경을 정리한다.
