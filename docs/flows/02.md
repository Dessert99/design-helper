# 02. 기존 디자인에 불만은 있지만 무엇을 바꿀지 정하지 못한 상황

[상황 목록으로](../flows.ko.md)

## 시작 조건

기존 버튼이 화면에 있다. 사용자는 답답하다고 느끼지만 비교할 속성을 지정하지 않았다.

## 예시 대화와 스킬 행동

> 사용자: 버튼이 좀 답답해 보여. 다듬고 싶어.
>
> 에이전트: 지금 버튼에서 어느 부분이 답답한가요?
>
> 사용자: 글자가 좌우 테두리에 너무 붙어 있어.
>
> 에이전트: 가로 padding만 늘려서 비교하면 될까요?
>
> 사용자: 응. 높이와 글자는 유지하고 가로 padding만 보자.

질문은 한 번에 하나씩, 사용자가 말한 불편함을 좁히는 방향으로 한다. 이 대화로 비교 축은 가로 padding, 유지할 조건은 높이와 글자로 정해졌다.

그때 프로젝트의 spacing 스케일에서 현재 가로 padding 주변의 5~7개 값을 뽑아 표본을 그린다. 예를 들어 좌우 padding이 같은 버튼이라면 양쪽을 함께 바꾸고 높이·문구·글자 스타일은 유지한다. 확인과 선택 처리는 [기본 비교 흐름](01.md)을 따른다.

## 끝나는 지점

비교할 속성을 구체화하고 그 속성의 비교 화면을 제공한다. 아직 사용자가 고르지 않았으므로 확정값은 없다.

## 다른 상황과의 차이

[01](01.md)은 속성이 처음부터 명확하다. [03](03.md)은 기존 대상 자체가 없어 불편함을 좁히는 질문으로 시작할 수 없다.

이 상황에서 에이전트가 `크기 → 여백 → 모서리 → 색` 순서를 정하거나, 답답하다는 말만 듣고 임의로 글자 간격을 선택하면 지침에서 벗어난다.
