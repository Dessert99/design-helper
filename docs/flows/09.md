# 09. hover·focus·disabled 같은 상태의 모습을 비교하는 상황

[상황 목록으로](../flows.ko.md)

## 시작 조건

기존 버튼의 기본·hover·focus·active·disabled 스타일이 있다. 이번 주문은 **hover 배경색**만 비교하는 것이다. 예시의 프로젝트 색상 후보는 A `#333333` · B `#444444` · C `#555555` · D `#666666` · E `#777777`로 가정한다.

## 예시 대화와 스킬 행동

> 사용자: 이 버튼의 hover 배경색을 비교해줘. 나머지 상태는 유지해줘.

1. 같은 버튼과 문구로 hover 배경색 후보를 만든다. 각 후보에서 다른 상태의 값은 현재 값으로 유지한다.
2. `실물` 행에는 사용자가 마우스를 올려 직접 조작하는 버튼을 놓는다.
3. `강제 상태` 행에는 default·hover·focus·active·disabled를 클래스로 고정해 나란히 놓는다. 마우스는 한 번에 한 버튼에만 올릴 수 있다. hover 모습을 고정하면 여러 후보의 색을 동시에 비교할 수 있다.
4. 검증 도구를 사용할 수 있으면 강제 hover 표본의 computed style을 읽어 서로 다른 색이 적용됐는지 확인한다. 실물 행에서도 직접 hover했을 때 같은 색이 나타나는지 살핀다.

> 사용자: B hover 색으로 갈게.
>
> 에이전트: 확정: hover 배경색 = B · #444444

## 끝나는 지점

hover 배경색만 확정한다. 다른 상태를 함께 확정하거나 컴포넌트의 접근성 동작 검증을 완료했다고 보고하지 않는다.

## 다른 상황과의 차이

[10](10.md)은 시간에 따른 변화를 비교한다. 여기서는 특정 상태에 도달했을 때의 모습을 비교한다.

시트는 모양과 상태 속성을 모사한다. 포커스 트랩, 키보드 탐색, 스크린리더 동작의 정확성은 실제 구현에서 검증해야 한다.
