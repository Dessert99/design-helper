# 08. 페이지의 배치와 구조를 비교하는 상황

[상황 목록으로](../flows.ko.md)

## 시작 조건

기존 페이지에 왼쪽 사이드바와 본문이 있다. 사용자는 사이드바 위치와 내용 순서는 유지하고 **사이드바 폭**을 비교하려 한다. 예시의 프로젝트 폭 스케일은 A 200px · B 224px · C 248px · D 272px · E 296px로 가정한다.

## 예시 대화와 스킬 행동

> 사용자: 사이드바 위치는 그대로 두고 폭을 비교해줘. 본문이 얼마나 남는지 보고 싶어.

1. 실제 페이지의 구조와 콘텐츠 양을 확인한다. 사이드바와 본문 사이의 간격, 전체 페이지 폭도 비교 조건으로 맞춘다.
2. 프로젝트의 실제 디자인으로 그린다. 색, 글꼴, 아이콘, 모서리, 그림자와 실제 메뉴 이름·본문 내용을 화면 그대로 쓰고, 모든 표본에서 똑같이 고정한다. 새로 만드는 부분에 따로 받은 디자인 요구사항이 있으면 그것으로 그린다.
3. 사이드바 폭만 다르게 한 표본을 그린다. 위치와 내용 순서는 유지한다.
4. 프로젝트에서 레이아웃이 달라지는 화면 폭(브레이크포인트)을 확인해 같은 A–E를 비교한다. 실제 페이지와 비슷한 수의 메뉴·본문·카드를 넣어, 사이드바가 넓어졌을 때 본문 공간이 얼마나 줄어드는지 볼 수 있게 한다.

> 사용자: C 폭으로 갈게.
>
> 에이전트: 반영·검증 후 보고: 사이드바 폭 = C · 248px

## 회색 뼈대로 보는 경우

사용자가 `뼈대만 보자`, `위치만 보자`, `와이어프레임으로`처럼 디자인을 빼고 위치만 보자고 명시할 때만 색·글꼴 장식·그림자·모서리를 걷어낸 무채색 블록으로 그린다. 블록에는 `네비`, `사이드바`, `본문` 같은 역할을 표시하고 명암으로 위계를 나타낸다. 배치를 묻는 질문이라는 이유만으로는 뼈대로 그리지 않으며, 이 요청은 그 주문에만 적용된다.

## 끝나는 지점

사이드바 폭을 기록하고 코드에 반영·검증한다. 페이지의 색이나 모서리 디자인을 이어서 정하지 않는다.

## 다른 상황과의 차이

[01](01.md)은 기존 컴포넌트의 속성 하나를 비교한다. 여기서는 배치와 구조가 축이고, 외관은 실제 디자인 그대로 고정한다. 색·그림자 같은 외관의 비교는 별도 주문이다.
