# 01. 기존 디자인에서 비교할 속성을 이미 정한 상황

[상황 목록으로](../flows.ko.md)

## 시작 조건

기존 카드가 있고, 사용자가 비교할 속성을 **그림자 블러**로 지정했다. 예시에서는 프로젝트에 4·8·12·16·24px 스케일이 있다고 가정한다. 실제 작업에서는 탐지한 프로젝트 값을 사용한다.

## 예시 대화와 스킬 행동

> 사용자: 카드 그림자 블러를 5가지로 보여줘.

1. 프로젝트의 스타일 체계와 현재 카드 값을 확인한다. 프로젝트 유틸리티나 CSS 변수 등 무엇을 사용해 그렸는지 사용자에게 알린다.
2. 프로젝트 밖 임시 작업 폴더에 시트와 서버를 준비한다. 기존 세션이면 같은 대상의 시트를 이어 쓴다.
3. A 4px · B 8px · C 12px · D 16px · E 24px를 그린다. 같은 배경·크기 안에서는 그림자의 색·농도·위치와 카드의 다른 속성을 고정한다.
4. 표본 옆에 값과 관찰할 점을 적는다. 기존 토큰을 그대로 쓸 수 있는지, 공통 토큰을 바꾸거나 새 토큰을 만들어야 하는지도 짧게 표시한다. 이것이 지침에서 말하는 비용 표시다.
5. 참조한 클래스·변수가 실제로 존재하는지, 브라우저가 최종 적용한 스타일 값(computed style)이 후보마다 다른지, 배치가 깨지지 않았는지 확인한다. 어느 후보부터 차이가 눈에 띄는지에 대한 `경계` 설명은 화면을 확인한 뒤 적는다. 검증 도구의 예외는 [공통 운영](operations.md#검증과발견)에 정리했다.

> 사용자: C로 갈게.
>
> 에이전트: 반영·검증 후 보고: 그림자 블러 = C · 12px

임시 메모에 선택한 축과 값을 기록하고, 해당 카드에 바로 반영한 뒤 검증한다. 토큰으로 골랐다면 해당 토큰이 가리키는 실제 값도 함께 적는다.

### 채팅으로 선택하는 경우

`난 B가 좋아`처럼 특정 후보를 고르면 별도 반영 요청 없이 적용한다. `A에서 블러를 더 보고 싶어`는 추가 비교 요청이므로 A를 기준으로 표본을 더 그린다. 선택 버튼과 서버 선택 기록은 사용하지 않는다.

### 배경·크기### 배경·크기·반복을 바꿔 보는 경우

일반 비교는 흰색·회색 배경과 두 크기를 함께 보여주며, 실제 UI에서 반복되는 요소는 반복해서 그린다. 프로젝트에 다크 표면이 있으면 그 배경도 비교할 수 있다. 사용자는 배경·크기·반복 버튼으로 한 조건만 따로 볼 수 있다. 작은 카드끼리 A–E를 비교하고, 큰 카드끼리 다시 A–E를 비교하는 식이다. 크기가 다른 두 카드의 차이를 블러 차이로 해석하지 않는다.

## 끝나는 지점

선택한 블러 값을 코드에 반영하고 검증 결과를 보고한다. 다음 속성 비교는 먼저 제안하지 않는다.
