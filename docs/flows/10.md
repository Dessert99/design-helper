# 10. 애니메이션의 움직임을 비교하는 상황

[상황 목록으로](../flows.ko.md)

## 시작 조건

기존 드롭다운이 CSS 애니메이션으로 열린다. 사용자는 **열리는 시간**을 비교하려 한다. 예시에서는 80·120·160·200·300ms를 후보로 쓰며, 프로젝트에 시간 스케일이 있으면 그 값을 우선한다.

## 예시 대화와 스킬 행동

> 사용자: 드롭다운이 열리는 시간을 비교해줘. 이동 거리와 easing은 그대로 두고.

1. 시간만 바꾼 A–E 표본을 만든다. 내용·이동 거리·easing은 고정한다.
2. `전체 재생` 버튼으로 함께 재생하고 다시 볼 수 있게 한다.
3. 사용자가 브라우저에서 직접 동작을 비교한다. 스크린샷은 정지 상태만 보여주므로 움직임을 확인한 근거로 삼지 않는다.
4. 비교 범위를 움직여 표본을 다시 생성하면 재생 상태가 초기화되므로 `전체 재생`을 다시 사용한다.

> 사용자: 실제 속도로 보니 D가 맞아. D로 갈게.
>
> 에이전트: 반영·검증 후 보고: 열리는 시간 = D · 200ms

### 느린 재생의 현재 한계

지침은 `1x / 0.25x`를 제공하고 실제 속도로 결정하도록 한다. 하지만 현재 CSS 예제는 모든 duration을 `4s`로 덮어쓰므로, 시간별 차이를 유지하는 0.25배속이 아니다. 이 예시는 **1x에서의 비교와 선택**으로 한정한다. 느린 재생이 올바르게 구현되었다고 가정하지 않는다.

### 모션 라이브러리를 사용하는 프로젝트라면

CSS easing과 spring 물리값을 동일한 것으로 취급하지 않는다. 라이브러리가 요소를 화면에 추가하거나 제거하는 시점도 시트와 달라질 수 있다. 실제 프로젝트가 spring을 쓰는지 확인한 뒤, CSS 표본과 동일하게 옮길 수 없는 부분을 반영 전에 알린다.

## 끝나는 지점

열리는 시간을 기록하고 바로 코드에 반영·검증한다. 반영할 때는 시스템에서 움직임 감소를 설정한 사용자를 위한 `prefers-reduced-motion: reduce` 대응도 다룬다.

## 다른 상황과의 차이

[09](09.md)은 고정된 상태의 모습이고, 이 상황은 시간에 따른 변화다. easing·이동 거리·stagger도 지침에 비교 축으로 등장하지만, 이번 주문에서 함께 바꾸지는 않는다.
