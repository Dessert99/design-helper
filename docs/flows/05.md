# 05. 한 속성을 확정한 뒤 다른 속성을 비교하는 상황

[상황 목록으로](../flows.ko.md)

## 시작 조건

같은 카드에서 그림자 블러를 비교 중이다. 블러 선택을 마친 다음 사용자가 모서리 비교를 별도로 주문한다. 예시의 모서리 스케일은 2·4·6·8·12px로 가정한다.

## 예시 대화와 스킬 행동

> 사용자: 블러는 C, 12px로 갈게.
>
> 에이전트: 확정: 그림자 블러 = C · 12px

메모에 기록하고 이 턴을 마친다. 에이전트가 모서리 비교를 먼저 제안하지 않는다.

> 사용자: 이제 같은 카드의 모서리를 비교해줘.

1. 메모에서 확정한 블러 12px를 읽는다.
2. 그 값을 모든 새 표본에 유지하고, 프로젝트의 radius 스케일로 모서리만 바꾼다.
3. 새 작업 단위이므로 문자는 A부터 시작한다. 과거 후보를 가리킬 때는 `그림자 블러 C`처럼 축을 함께 말한다.
4. 같은 시트 아래에 새 비교를 붙인다. 이전 블러 표본은 남긴다.
5. 메모 자체를 결정표나 머리말로 화면에 출력하지 않는다.

> 사용자: 모서리는 B로 갈게.
>
> 에이전트: 확정: 모서리 = B · 4px

## 끝나는 지점

모서리 선택을 기록하고 멈춘다. 블러와 모서리의 선택은 기록되어 있고, 프로젝트 코드 반영은 별도 주문이다.

## 다른 상황과의 차이

[04](04.md)는 확정 전 같은 축을 더 비교한다. 여기서는 앞선 축의 선택이 끝났고, 사용자가 새로운 축을 주문했다. [06](06.md)처럼 이전 결정을 수정하는 상황도 아니다.
